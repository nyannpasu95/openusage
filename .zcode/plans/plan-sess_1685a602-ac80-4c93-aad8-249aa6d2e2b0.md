## 目标
给 DeepSeek 插件在 detail 区域加一行 **Spent Today**(今天到目前为止的消费),用余额差值法近似计算。范围明确:**仅这一行**,不引入柱状图/历史。

## 关键事实(来自调研)
- DeepSeek API 只暴露 `GET /user/balance`,**没有按天的消费查询接口**(`docs/providers/deepseek.md:12` 已记载)。所以"今天花了多少"只能用 `今日首次见到的余额 − 当前余额` 来近似。
- 插件可以通过 `ctx.host.fs` + `ctx.app.pluginDataDir` 持久化状态文件(copilot/antigravity/codex 都用这个模式),这是跨 probe 调用持久化状态的唯一方式(每次 probe 都在全新 QuickJS runtime 里跑)。
- 日期 key 复用 codex 的 `dayKeyFromDate(date)`(`plugins/codex/plugin.js:422`)。

## 实现算法(余额差值法)
维护一个状态文件 `pluginDataDir/spent-today.json`:
```json
{
  "day": "2026-07-20",        // 本地日期 key,用 dayKeyFromDate(new Date())
  "baseline": { "CNY": "8.66", "USD": "5.00" },  // 今日首次见到的各币种余额(total_balance)
  "lastToppedUp": { "CNY": "8.66", "USD": "4.00" } // 上次见到的 topped_up_balance,用于识别充值跳变
}
```

每次 probe 的逻辑:
1. 算出 `todayKey = dayKeyFromDate(new Date())`。
2. 读状态文件。
3. **跨天重置**:如果 `state.day !== todayKey`(或文件不存在),把 `baseline` 设为本次的 `total_balance`,`lastToppedUp` 设为本次 `topped_up_balance`,写回状态,输出 `Spent Today = —`(首次刷新无基线)。
4. **充值补偿**:如果本次 `topped_up_balance > state.lastToppedUp`(同币种),说明用户充值了 —— 把 `baseline` 同步抬高这个差额,再更新 `lastToppedUp`。(granted 余额无法和过期区分,不补偿,写进文档。)
5. **计算消费**:`spent = baseline − current_total`(每个币种独立算,clamped 到 ≥0,避免 API 小波动负值)。
6. 多币种按现有 `formatBalanceList` 的风格拼接(`¥1.20 CNY`、`$0.50 USD + ¥1.20 CNY`)。
7. 所有币种都为 0 时显示 `¥0.00 CNY`(今天没消费)。写状态用 try/catch 包住,失败只 `ctx.host.log.warn`,不影响主流程。

### 3. `plugins/deepseek/plugin.test.js`(回归测试)
- 新增测试用例(mock `ctx.host.fs` 的 in-memory map 已在 `test-helpers.js` 提供好):
  - 首次刷新(无状态文件)→ Spent Today 为 `—`,状态文件被写入 baseline。
  - 同一天第二次刷新,余额下降 → 正确显示差额,币种符号/拼接正确。
  - 跨天(`ctx.nowIso` 改一天)→ 状态重置,Spent Today 回到 `—`。
  - 中途充值(topped_up_balance 上升)→ baseline 抬高,Spent Today 不被充值污染。
  - 余额上升但非充值(granted 过期反向场景)→ clamped 到 0,不显示负数。
  - 状态文件损坏 → 不崩溃,降级为 `—` 并重建 baseline。
  - writeText 抛错 → 主流程仍返回 4 行余额。

### 4. `docs/providers/deepseek.md`
- 在 "Output" 段加一条 **Spent Today (detail text)** 的说明。
- 新增一个 **"Spent Today 的近似与局限"** 小节,明确写:
  1. 只统计 app 运行期间的消费(基线是当天首次刷新的余额)。
  2. Granted 余额过期会被误算成消费(DeepSeek API 不区分)。
  3. 充值会被自动补偿基线。
